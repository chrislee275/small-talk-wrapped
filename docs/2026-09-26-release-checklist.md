# Public release checklist

This candidate is local only. No GitHub repository, remote or deployment is authorized by this document.

- [ ] Owner reviews all fictional stories, SVG placeholders and screenshot selections.
- [ ] Owner chooses final repository name, GitHub account and public-release permission.
- [ ] Owner decides project code/artwork licensing; preserve dependency notices.
- [ ] Review this candidate's full fresh history, file inventory and build output for private material.
- [ ] Re-run privacy checks after any content, asset or history change.
- [ ] Review known limitations in QA; perform real-device and assistive-technology checks as needed.
- [ ] Check README claims against actual test evidence; do not add unmeasured performance claims.
- [ ] Confirm no original-site links, private screenshots, source references or deployment identifiers have been added.
- [ ] If approved later, push only this candidate's new history. Do not connect the original repository.

No automatic publishing workflow is included. Deployment of a separate demo is a later, separately authorized action.
